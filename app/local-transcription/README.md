# Offline WAV transcription

This independent macOS 12 Swift package uses Apple's Speech framework for an explicitly selected, finalized WAV file. It is not a Krisp model loader or a parity implementation. It ships no speech weights, makes no downloads, and has no cloud recognition path.

`OfflineTranscriber` is a main-actor service with one operation at a time. It reads the current OS authorization state before file validation. It requires a recognizer for the requested locale, rejects locale fallback, and checks both `supportsOnDeviceRecognition` and `isAvailable`. It repeats permission and capability checks after file validation. Every Speech request sets `requiresOnDeviceRecognition = true` and `shouldReportPartialResults = false`. Unsupported on-device recognition fails before a recognition task starts. No retry can switch to a remote recognizer.

## Caller contract

Obtain the file from an explicit user selection and construct `UserSelectedWAV(userSelectedURL:)`. The package cannot prove the user's intent; the caller owns that UI boundary. It rejects non-file URLs and filenames without a WAV extension. Validation runs on a worker task, requires a regular file, rejects a symlink at the selected filename, checks RIFF/WAVE structure, and opens it through AVAudioFile to reject an empty or undecodable recording. RF64 and other WAV container variants are not supported. The file must remain unchanged for the whole operation. Speech later opens the selected URL, so validation does not reserve the file against replacement.

The caller must decide when to ask for OS consent. `OfflineTranscriber.authorizationStatus` returns `notDetermined`, `denied`, `restricted`, `authorized`, or `unknown` without prompting. `transcribe` never requests permission. The separate `requestAuthorization()` method may present the OS prompt and must only follow an explicit user action. The integrating app must supply a nonempty `NSSpeechRecognitionUsageDescription` in Info.plist. The method rejects a missing description before calling the system. This package and its tests do not change app permissions.

Use an explicit locale and call `transcribe(_:localeIdentifier:timeoutSeconds:)`. The result has final text, the actual locale, and Speech's segment text, timestamps, durations, and confidence values. Segment timing and confidence must be finite and within the documented nonnegative ranges. No speaker identities, diarization, summaries, translations, or accent conversion are generated. Segment times are returned as reported by Speech and are not clamped to recording duration. A storage adapter must decide how to handle any timing discrepancy.

`cancel()` cancels the current recognition task and publishes a cancelled phase. Cancelling the caller's Swift task also cancels recognition. Cancellation and a final callback can race; the first terminal event processed by the service wins. File validation uses blocking OS file operations on a worker task. Cancellation prevents recognition from starting, but validation I/O must return before the awaiting caller can finish. It cannot interrupt a blocked filesystem call.

The default recognition timeout is 120 seconds. A caller may choose a finite value greater than zero and at most 3600 seconds. The timer begins when recognition starts, after file validation. Timeout cancels the Speech task and returns `timedOut`. Duplicate or late callbacks cannot resume the continuation twice or overwrite a newer operation. Concurrent requests return `busy`. The service retains its recognizer during recognition and releases task state after any terminal event.

`phase` exposes idle, file validation, recognition, completed, failed, and cancelled states. Admission failures such as missing authorization do not start an operation or replace the previous phase. Typed failures identify authorization, locale, capability, availability, cancellation, timeout, and invalid results. Apple recognition errors preserve their domain, code, and description. AVFoundation or Foundation validation errors can also propagate directly. All engine management runs on the main actor; Speech performs recognition asynchronously and file validation runs off that actor. This is not an audio callback API.

## Verification

Run `./verify`. Fourteen contract tests and the release build pass on this Mac. Test recognizers, authorization, and completion callbacks are injected internally. They verify fail-closed capability and authorization checks, permission revocation, rejection of locale fallback, exactly-once completion, synchronous failure, busy rejection, cancellation, stale callbacks after restart, recognition timeout, and invalid timeout values. A temporary generated silent WAV checks the real AVAudioFile validation path and the actual Speech request's offline flag. Malformed and symlink fixtures are rejected.

Verification never requests authorization, starts an OS recognition task, or reads a real user recording. Successful offline transcription, OS cancellation behavior, available language assets, real transcript accuracy, long-recording limits, and latency remain untested. Apple can report missing assets, disabled Dictation, unsupported locales, service interruption, or recognition failure. The package propagates these errors without cloud fallback or an automatic asset download. The offline request flag and capability checks are tested; they are not a network traffic audit of Apple's framework.

A runtime test needs an integrating app with the usage description, an explicit user consent action, OS Speech authorization, supported on-device language assets, and a WAV selected by the user. No microphone permission is requested because this API does not capture audio. The caller must keep any security-scoped access from a sandboxed file picker valid during transcription.

## SDK basis

Implementation uses the installed macOS SDK's `Speech.framework/Headers/SFSpeechRecognizer.h`, `SFSpeechRecognitionRequest.h`, `SFSpeechRecognitionTask.h`, and `SFTranscriptionSegment.h`. The recognizer header states that on-device requests can be honored only when on-device recognition is supported, that locale creation can fall back, and that authorization callbacks are not guaranteed to run on the main queue. The task header documents cancellation and error propagation. The package returns callbacks to the main actor and rejects a recognizer whose locale differs from the requested one.
