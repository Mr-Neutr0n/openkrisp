# Independent audio driver routing

Run `./verify` on macOS with Command Line Tools. It builds an unsigned host-architecture bundle at `build/LabVoiceAudio.driver`, checks its plist, and loads its factory with `dlopen` in a standalone test process. It does not install a driver, register a HAL device, restart CoreAudio, open hardware, or inspect the original app. C++20 is required by the transport dependency. All source and identities are independent.

Hidden devices reject default-device eligibility and can be found by UID translation. Hidden is a visibility setting, not access control. The format targets come from `../../driver-declarations.json` and `../../driver-runtime-findings.md`. Mono devices declare the observed 480-frame nominal buffer and 15..480 range. ## Frame routing

The app feeds processed mono data to App Feed. The driver stores that output in a mono ring. Public Microphone reads that ring. Public Speaker stores its stereo output in a separate ring. App Monitor reads that ring for the app to process and send to hardware.

Each route uses the bounded in-process `Transport` from `../audio-transport/transport.hpp`, unchanged. Both rings have 32,768 frames. Allocation occurs during bundle initialization, before IO callbacks. A callback accepts at most 4,096 frames. Callbacks allocate no memory, acquire no mutex, spin on no retry loop, access no files, and log nothing. A try-once atomic guard prevents concurrent writers from violating the transport's single-producer contract. Concurrent producer entry returns an error. Readers may run concurrently.

SDK `AudioServerPlugInIOCycleInfo.mOutputTime` specifies the first output frame. `mInputTime` specifies the first input frame. The driver requires valid sample-time flags, finite nonnegative integral sample positions, and bounded indices. Missing, fractional, or negative sample positions return an error. Fractional timestamps under aggregate-device drift compensation remain unsupported. `mCurrentTime` and `mNominalIOBufferFrameSize` do not select ring positions.

For an output frame F, the corresponding input frame is F + 960. An input read at R requests ring frame R - 960. Early frames before the delay are zero. The compile-time `LABVOICE_ROUTE_DELAY_FRAMES` definition sets the fixed delay when building `driver.cpp`. It defaults to 960, which is 20 ms at 48 kHz. It must be less than ring capacity. There is no live delay setter. The checked-in host test checks the default delay. Change its expected frame offsets when verifying another build configuration. This delay is an independent buffering choice, not inferred original behavior or an end-to-end latency measurement.

The transport leaves forward timestamp gaps silent, returns zero for overwritten frame stamps, and rejects backward or duplicate producer timestamps. Reads return zero if the producer is stopped or its last publication is older than 250 ms of monotonic wall time. That threshold is an independent failure policy. On the last producer client's stop or removal, the route advances a generation counter inside the lifecycle lock. Writers capture that generation before checking running state. A writer that finishes after its generation changes cannot publish a readable generation and returns a not-running error. The first accepted write in the new generation sets that generation's minimum readable frame before it publishes the generation. Readers require matching current and published generations, apply that frame floor, and clear copied samples if the generation changed during the read. The ring is never reset or freed during IO. This prevents a late pre-stop write from becoming readable after restart without assuming that StopIO waits for callbacks. A read already completing before stop takes effect may return its old-generation samples. The producer must continue on the shared timeline; backward time after a host resynchronization is unsupported. Reader stop does not flush a running producer's history.

All four devices share a fixed `mach_absolute_time` anchor, seed 1, and clock domain `0x4c564143`. Zero timestamps use a 16,384-frame period. The local SDK requires a minimum period of 10,923 frames. Nominal audio buffer sizes are not timestamp periods. The clock declares the raw algorithm and stable clock. No timeline reset occurs at start or stop.

The interface also provides COM lookup and reference counts, sized property reads, scope checks, retained CF strings, immutable formats, at most 64 registered clients per device, idempotent client start/stop, and running-state notifications. Only client IDs are retained. Dynamic creation and format changes return unsupported-operation errors.

## Verification and limits

The host test loads the compiled bundle and checks identities, formats, property sizes/scopes, hidden/default eligibility, multiple-client lifecycle, notifications, and clock advancement. It sends known mono and distinct stereo samples through the actual WriteMix and ReadInput interface calls across device pairs. It checks exact sample transfer, the 960-frame delay, startup zero prefix, timestamp gaps, duplicate rejection, producer stop/restart invalidation, 250 ms stale silence, ring overwrite, callback bounds, wrong streams, null buffers, and invalid timestamps.

A separate test-only bundle adds a deterministic writer pause hook. The concurrency test pauses a pre-stop write after its generation capture, completes stop/start, reads while the write is paused, then allows the old write to finish. It checks silence before and after late publication, rejection of the old callback, continued silence for its frames after a new write, and exact transfer of the new-generation samples. The production bundle contains no pause hook.

These tests establish in-process routing in the standalone host. They do not establish coreaudiod acceptance, scheduling order, realtime deadline performance, app capture/playback, DSP, client isolation, signing, installation, or parity. The fixed delay must be tested against actual output-ahead/input-behind HAL scheduling. An output frame can arrive after a reader requests it; the defined result is silence. Ring capacity and delay do not guarantee that all host schedules can be served.

The local SDK forbids an AudioServerPlugIn from calling the client HAL API. This driver makes no such call. A GUI app may use that API to open companion endpoints through the host. This design needs no cross-user POSIX shared memory or Mach service. No IPC is implemented. A future authenticated Mach-service design would need the accessed services declared in `AudioServerPlugIn_MachServices` and a separate ownership review.

An approved development driver is installed for bounded tests. Its initial package and the class-filter correction both registered the plug-in but exposed no devices. Real HAL acceptance, a GUI endpoint client, producer authorization, aggregate-device timing support, engine integration, hardware routing, and capture-based audio comparison remain required. No parity pass is claimed.

### Installed discovery checkpoint

The first approved installation on October 13, 2026 loaded the independent remote driver service. A read-only client translated `dev.hari.labvoice.audio` to plug-in ID 49, but its client-visible DeviceList and OwnedObjects lists were empty. This confirms plug-in registration without usable device publication. It does not prove an ad-hoc signing rejection or a hidden-device translation defect.

The initial driver ignored the AudioClassID qualifier on OwnedObjects. It returned devices for a box-class query and streams for a control-class query. The SDK requires matching classes or their subclasses. The standalone host reproduced this defect. The driver now filters owned children by the requested classes and rejects malformed qualifier sizes. Unqualified lists and UID translation remain unchanged. Tests cover device, stream, control, box, AudioObject superclass, and multiple-class queries. The guarded retest of the corrected package still returned the same missing feed UID. Class filtering is a required contract fix but did not resolve installed discovery.

An opt-in discovery trace is built with `LABVOICE_DISCOVERY_TRACE=1 ./package`. It writes to `build/package-discovery-trace`, leaving the normal signed package untouched. The trace is absent from default builds. At most 512 entries per driver instance log factory/query/initialization and Has/Get/Size property calls, local object IDs, selectors, scope, element, class qualifiers, status, and returned class/object IDs. It logs no samples, user strings, or IO callbacks. Root performs any guarded installation and restart. If the trace does not establish a cause, rollback is preferable to another speculative patch.
