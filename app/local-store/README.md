# Local session storage

This independent Swift library saves completed recordings and transcripts to a caller-selected directory. It has no network client, account, analytics, automatic retention, or model integration. It does not capture or transcribe audio.

`LocalStore(root:createIfMissing:)` defaults to `true` for the app's default directory. Explicitly selected and persisted locations must pass `false` on every reopen. Strict opening requires an existing plain directory with read, write, and search permission. A missing, inaccessible, or symlink location throws instead of creating a directory or selecting another library. Admission does not chmod an existing directory, migrate sessions, or delete entries. Callers own location persistence and must commit the preference only after admission succeeds.

Each operation rechecks root access and the directory's device/inode identity. Disappearance, loss of access, or replacement invalidates that `LocalStore` instance. Reopening a different directory requires an explicit caller decision. These checks detect changes between operations; path-based file operations are not a race-proof transaction against concurrent filesystem replacement. Permission admission also does not guarantee free space or future write success.

`LocalStore.save` imports a finalized WAV and transcript segments, or a transcript alone. It copies recordings in 1 MiB blocks into a private staging directory. Files use mode 0600 and new directories use 0700. The original recording stays unchanged. A successful save publishes the complete session directory by rename on the same volume. Failed saves keep their staging directory and stay out of normal history. `inventory` reports these entries for a future recovery UI. It also isolates corrupt sessions so other history remains readable.

The manifest stores a schema version, UUID, title, start time, duration, segments, and an optional fixed recording filename. Start time uses Swift Date's numeric seconds since 2001-01-01 UTC and retains fractional seconds. Search matches titles, text, and speakers. Text export refuses to overwrite an existing file. Deletion requires an explicit caller action. No automatic deletion runs.

Run `./verify` with the macOS Swift toolchain. Tests exercise a complete audio import and export, unchanged source bytes, private file modes, failed imports and reopening, corrupt manifests beside healthy sessions, timing validation, history order, file reference validation, strict selected-root admission, permissions without chmod, two independent reopened libraries, and root disappearance/replacement.

The catalog supports local storage, transcript search, save, and permission/storage errors. Source: REA Evidence `ev_ece7c942d90e27f063fd1be188d354a1a8d0f289e59aadea32bb6dc209566fa7`. The original storage schema is unknown. This format and its behavior are implementation choices, not a compatible reader for Krisp files.

Capture, ASR, pause/resume, recovery controls, location persistence, and activity locking belong to the caller. The desktop integration uses the shared store API; original location-selection, reopening, migration, and persistence semantics remain unknown. This package neither applies a four-hour quota nor automatically removes old recordings. Audio import checks the RIFF/WAVE signature, not every media chunk. The caller must finalize and validate the audio. File synchronization and same-volume rename do not prove survival of every power-loss case. Export can leave a partial new file if disk I/O fails. A caller must show that error. Disk operations must not run inside audio callbacks.


## Reviewed transcript replacement

`transcriptionSnapshot(for:)` opens an existing recorded session and binds a review to its session data and file identities. `replaceTranscript(_:expected:)` validates segment times, checks the expected snapshot, writes and synchronizes a private temporary manifest, rechecks the snapshot, and atomically renames it over `session.json`. It keeps the session UUID, title, start time, duration and recording filename. Audio is never opened for writing or copied. Failed validation leaves the existing manifest unchanged.

A shared process lock serializes review snapshots, transcript commits and deletion across store instances. A second review based on an old manifest is rejected. Deletion ordered after a successful commit remains a valid explicit action. The caller must hold its library activity lease. Root and session directories bind device/inode; manifest and recording files additionally bind size and nanosecond modification/change times. This detects ordinary replacement and mutation, not cryptographically identical bytes or hostile concurrent external writers. The rename is atomic, but this API does not promise power-loss directory durability. A crash before rename can leave a private `.transcript-*` file that history ignores.
