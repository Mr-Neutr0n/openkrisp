# Audio transport

This original C++20 transport stores a bounded history of Float32 audio frames. Use one instance for a mono microphone stream and another for a stereo speaker stream. Both use 48 kHz metadata. Capacity is chosen at construction. The captured device buffer sizes do not prove the required history capacity or measured latency.

Construct and destroy the transport outside audio callbacks. One producer calls `write`. Readers call `read` with absolute sample frame indices. Input and output buffers must contain `count * channels` samples. The caller owns these buffers and keeps them valid for the entire call. Do not destroy or move the transport while any callback uses it.

The producer must advance frame indices and provide a monotonic nanosecond heartbeat. A forward jump creates a gap. Backward writes, backward heartbeat time, empty writes, and timeline exhaustion fail without changing stored frames. Start a new transport to reset the timeline. The supported timeline ends before `UINT64_MAX / 2`, which also prevents revision counter rollover. Frame indices name sample time within this timeline. They are not host clock timestamps.

Readers pass time from the same monotonic clock and a stale timeout. A stale producer, future heartbeat, missing frame, overwritten frame, or overlapping overwrite returns zero for that frame. Readers do not retry. A concurrent write can therefore cause a silent frame even when that frame was available briefly. A read snapshots heartbeat freshness once per call. A write in progress can publish individual frames before it publishes the block heartbeat. The protocol does not promise block atomicity.

All shared slot fields are lock-free atomics. Sequentially consistent revision, frame, and sample operations place each access in one total order. A reader accepts a frame only when both revision reads match an even nonzero revision and the frame index matches. Every sample load then falls between the same two publication boundaries. This prevents data races and mixed stereo frames during overwrite. Callbacks have no locks, allocations, system calls, or unbounded retry loops. Cost grows with the caller's frame count. Sequentially consistent atomics have a cost that must be measured under HAL load.

`Protocol` is a fixed-width 24-byte metadata description, version 1, with Float32 interleaved format code 1. A future shared-memory implementation must define byte order, placement, initialization, process-shared atomic behavior, and lifecycle. Do not map the current C++ object or its pointer into another process. No global shared object exists here.

Run `./verify` on macOS with clang. It checks mono and stereo transport, silence before publication, ring wrap, overwrite, forward discontinuity, heartbeat expiry, invalid writes, frame-index overflow, and concurrent producer/reader sample consistency. It also runs AddressSanitizer, UndefinedBehaviorSanitizer, and ThreadSanitizer. Python 3 creates and cleans temporary build directories. It does not prove absence of all scheduling failures.

A HAL driver, host clock to sample clock conversion, producer restart coordination, real-time scheduling bounds, measured callback cost, and comparison against actual Krisp audio streams remain missing. This module performs no noise processing and makes no audio-quality or parity claim.

## macOS shared memory

`shared_transport.hpp` implements a separate transport for two processes on the same macOS ARM64 machine. The owner creates a POSIX shared-memory name with `O_EXCL` and mode `0600`. A reader attaches with `O_RDONLY` and a read-only mapping. Setup rejects an object with a different effective user ID, mode, size, protocol version, or format. Owner and attacher setup run outside callbacks. The owner destructor marks the mapping closed, unmaps it, closes its descriptor, and unlinks the name. Existing readers retain their mappings and return silence after closure. No installation or global default object is used.

The caller must supply a fresh unpredictable name through a trusted local control channel. Same-user processes can access a discovered name. This mechanism does not isolate hostile processes running as the same user. No callback uses the name or opens a descriptor. Create a new object and name for producer restart. Do not transfer producer ownership within an existing mapping.

The ABI uses a 64-byte header followed by 32-byte frame records. Fixed-width little-endian integers occupy explicit offsets. Compile-time assertions check size, alignment, and always-lock-free 32-bit and 64-bit Clang atomic operations. All mutable shared words use `__atomic` operations with sequential consistency. No C++ atomic object, heap pointer, mutex, or process-local runtime state appears in mapped bytes. macOS can report page-rounded backing size. The header records the exact audio layout size, and attachment accepts less than 64 KiB of page padding. The implementation targets macOS ARM64 and Clang. It does not claim a portable ISO C++ process-shared atomic guarantee or compatibility with other CPUs and compilers.

One owner thread writes. Any number of attached readers can read. Each callback accepts at most 960 frames. An oversized read returns zero copied frames and does not touch the caller buffer. A valid-sized read fills every output sample. The caller uses the same `CLOCK_MONOTONIC` nanosecond domain in both processes. No clock syscall runs inside the transport callback. An owner that exits without its destructor can leave its name behind. Its heartbeat expires and readers return silence. A control process must remove abandoned names. The transport does not detect PID death or perform ownership takeover.

`./verify` now also executes a distinct reader executable against each mono and stereo owner. It checks initial silence, rejection of writes from an attacher, concurrent frame/sample consistency across many wraps, heartbeat expiry using the real monotonic clock, a forward gap, exclusive creation, close notification, and name removal. The process tests pass in release and with AddressSanitizer plus UndefinedBehaviorSanitizer. ThreadSanitizer checks the original in-process transport, and cannot observe races between distinct processes. A separate abrupt-exit test bypasses the producer destructor, checks stale silence through a surviving mapping, and explicitly removes the abandoned name. No test proves callback deadlines, page residency, or HAL timing.
