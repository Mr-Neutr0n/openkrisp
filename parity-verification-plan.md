# Local parity verification plan

No end-to-end parity scenario below has passed. Existing evidence includes static boundaries and read-only device-property snapshots. Original behavior, supported settings, model semantics and performance thresholds remain unknown. Full parity requires a measured original baseline for every retained behavior and the same measurements from the independent app.

Use the same Mac, macOS version, physical devices, sample rates, buffer sizes and input recordings for both runs. Record versions, device identifiers, permission state, selected controls and output files. Keep original-app probes within the declared REA runtime boundary. Use synthetic audio and consented recordings. Do not use account data as a fixture.

| Scenario | Concrete procedure and measurements | Original baseline still needed |
| --- | --- | --- |
| Virtual microphone routing | Feed a known speech and impulse recording into the selected physical input. Select the virtual microphone in a separate recording app. Save its output with processing off and on. Verify channel identity, sample count, gain, silence behavior and absence of duplicate audio. Repeat while another client opens the same device. | Device-property capture establishes a mono 48 kHz Float32 microphone. Bypass behavior and concurrent-client behavior remain unknown. |
| Virtual speaker routing | Send a known stereo signal from a separate app to the virtual speaker. Capture the selected physical output. Compare channel ordering, gain, processing, mute and volume mapping. Change the system default output while the stream runs. | Device-property capture establishes a stereo 48 kHz Float32 speaker. Routing policy, processing, volume mapping and default-device policy remain unknown. |
| Device lifecycle | Start a stream, unplug a USB device, reconnect it, switch to Bluetooth, change sample rate, sleep and wake the Mac, then quit the app. Record missing frames, recovery time, selected devices and final system defaults. Reopen a client after app exit. | Fallback selection, device restoration, stream recovery and quit behavior are unknown. |
| Noise suppression | Mix the same clean speech with keyboard, fan, music and competing speech at controlled input SNRs. Compare original and rebuilt outputs against clean speech. Measure noise attenuation, speech distortion, intelligibility and speech deletion. Review consonants and quiet speech in blind listening trials. | Supported noise categories, quality modes and acceptable metric differences are unknown. Do not assign a parity margin before baseline measurements. |
| Echo cancellation | Play a known far-end signal through speakers while recording near-end speech. Include far-end only, near-end only and overlapping speech, then change acoustic delay. Measure residual echo, echo return loss enhancement, near-end attenuation and recovery time. | Whether the original enables this path, its reference routing and thresholds are unknown. AEC exports alone do not establish an active mode. |
| Latency and sustained load | Capture synchronized impulses before and after each virtual path. Report added latency distribution, jitter, dropped frames, CPU, memory and energy for bypass and each active mode. Repeat with simultaneous mic and speaker streams for 60 minutes. | Original latency distribution, supported buffer sizes, load limits and dropout tolerance are unknown. |
| Settings lifecycle | Enumerate controls through the original UI. Change each control individually, capture its audio or routing effect, quit and reopen, then reboot. Record initial defaults, persisted values, reset behavior and unavailable controls after device removal. Repeat permission deny, grant and revoke paths. | The catalog names candidate controls. Reachability, defaults, hotkeys and storage keys remain unknown. Runtime control inventory must precede parity claims. |
| Model lifecycle | Observe which retained mode loads which model through REA. Test cold start, first use, repeated use, switching modes, missing model and incompatible model. Measure load time, peak memory, error state and uninterrupted audio during switches. | The bundled manifest declares eleven model entries and maps model types to filenames. Eight occur in the app inventory, with three further filenames found in the downloaded-model folder. Active mode selection, file semantics and offline initialization remain unknown. |
| ASR and language detection | If original offline execution is established, run consented multilingual recordings with reference transcripts. Record word error rate, detected language, first-result delay, final-result delay and stop/flush behavior. Restart with network unavailable. | Offline support, language set, model dependencies, transcript schema and quality thresholds are unknown. Native handlers alone do not qualify this function as retained local parity. |
| Diarization | If original offline execution is established, process single-speaker, alternating-speaker and overlapping-speaker recordings with reference speaker times. Measure diarization error, label consistency, timestamp error and live-result delay. | Offline availability, speaker limits and accepted timestamp/error differences are unknown. |
| Recording and redaction | If the original exposes local recording, record known tones and speech, pause and resume, stop, then reopen the result. Measure container/codec, sample rate, channels, duration, pause semantics and finalization. If redaction is exposed, compare the specified interval and retained surrounding audio. | UI reachability, formats, destination, redaction argument semantics and interrupted-recording recovery are unknown. |
| Translation and RTC transcription | Establish through REA whether each path runs without cloud services. Only then test supported languages, synthesized playback, interruption, input/output timing and error states with fixed fixtures. | Their local availability is unknown. WSS and Daily symbols require a boundary investigation before retention decisions. |
| Local-only operation | With network unavailable, cold start the independent app, select devices, load every retained model and run every retained processing mode. Capture attempted network connections and confirm no upload of test audio, transcripts or diagnostics. | This is an explicit rebuild requirement. It does not establish which original functions were local. |
